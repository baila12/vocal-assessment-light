# 声乐评估系统 (VAS) — 产品需求文档 v1.0

> 版本: v1.0 | 日期: 2026-06-05 | 状态: 当前

---

## 1. 产品概述

### 1.1 一句话定位

**纯离线、无服务器的本地声乐五维评分 Web 应用** — 一键启动，浏览器即用，所有数据留在本地。

### 1.2 目标用户画像

| 用户类型            | 特征                                 | 使用频率    | 核心诉求                           |
| ------------------- | ------------------------------------ | ----------- | ---------------------------------- |
| **声乐学生**  | 有规律练习习惯，需要量化反馈追踪进步 | 每天 1-3 次 | 详细诊断 (逐句评分) + 历史进步曲线 |
| **K歌爱好者** | 非专业背景，偶尔使用，追求趣味       | 每周 1-3 次 | 快速评分 + 简单直观的反馈          |
| **声乐教师**  | 专业背景，多学生管理场景             | 每天多次    | 对比分析 (DTW) + 客观评分辅助教学  |

### 1.3 核心价值主张

| 价值点                 | 说明                                                     |
| ---------------------- | -------------------------------------------------------- |
| **纯离线隐私**   | 所有数据本地存储，不上传云端，无需联网                   |
| **五维专业评分** | 音准/节奏/气息/技术/艺术，非娱乐性质的玩具评分           |
| **浏览器即用**   | 一键启动 Flask 服务，浏览器自动打开，零配置              |
| **人声分离**     | Demucs 自动分离伴奏，在纯净人声上评分更准确              |
| **DTW 对比**     | 与标准演唱逐帧对齐对比，知道「差在哪」而不仅是「差多少」 |

## 2. 用户场景

### 场景 A：声乐学生日常练习

> **Given** 声乐学生刚完成一段 3 分钟的流行歌曲练习录音
> **When** 打开系统，上传录音，选择 Quick 模式
> **Then** 15-20 秒内获得五维评分 + 雷达图 + 改进建议
> **And** 历史记录自动保存，可查看本周进步趋势

### 场景 B：专业用户深度诊断

> **Given** 用户录制了带钢琴伴奏的完整演唱 (MP3 格式)
> **When** 选择 Professional 模式上传
> **Then** Demucs 自动分离人声 (~130-170s CPU)
> **And** 在纯净人声上计算五维评分 + 逐句评分 + 频谱图/基频图/能量图
> **And** 每句标注问题 (音偏高/气息不稳/节奏偏移)

### 场景 C：上传翻唱 → 自动匹配标准歌曲 ★v6.0

> **Given** 标准曲库中有 "月亮代表我的心 - 邓丽君" (特征已预提取)
> **And** 用户录制了同歌曲的翻唱版本
> **When** 用户上传翻唱音频到系统
> **Then** 系统自动提取音频特征 (BPM/调性/频谱指纹)
> **And** 在 5 秒内搜索标准曲库找到匹配歌曲 (置信度 ≥ 0.7)
> **And** 自动切换为 DTW 对比模式，使用匹配的标准音频作为参考
> **And** 返回对比评分 + 音准/节奏偏差 + 问题段落
> **And** 若曲库中无匹配 → 回退绝对评分，标注 `fallback_reason: "no_match"`

### 场景 D：选歌后录音对比 ★v6.0

> **Given** 用户打开歌曲选择页面
> **When** 浏览曲库 (按难度/风格筛选)，选择 "月亮代表我的心"
> **Then** 进入录音准备页，显示标准歌曲信息 + 原唱试听
> **And** 用户录音过程中实时显示音高对比 (当前 vs 标准)
> **And** 录音完成后自动执行 DTW 对比，不需要再次搜索匹配
> **And** 支持仅上传已有录音 (跳过实时录音步骤)

### 场景 E：对比标准版本 (手动)

> **Given** 用户有自己的演唱录音和原唱/标准版本
> **When** 使用手动对比分析功能，显式上传两个音频
> **Then** DTW 逐帧对齐后给出相对评分
> **And** 音高曲线叠加对比，偏差区域高亮
> **And** 自动诊断：音准偏差 +15 音分，节奏偏快 120ms

### 场景 F：非人声/噪声拦截

> **Given** 用户误上传了白噪声 / 纯音乐 / TTS 合成语音
> **When** 系统进行人声质量检测
> **Then** 检测为 `is_voice=false`，总分返回 `0.0`
> **And** 前端显示「未检测到有效人声」警告，不产生历史记录污染

#### 开源算法移植 (轨道B，v5.18-v6.1)

> 从 GitHub 开源项目借鉴/移植经过学术验证的算法，通过 Feature Flag 逐个接入，提升核心评分区分度。

| 功能              | 开源来源                                                                       | 版本  | Flag                           | 说明                                                  |
| ----------------- | ------------------------------------------------------------------------------ | ----- | ------------------------------ | ----------------------------------------------------- |
| 多尺度 HNR        | [VoiceLab] de Krom 1993                                                        | v5.18 | `enable_multiscale_hnr`      | 短/中/长窗 HNR + 稳定性，提升 Breath/Technique 区分度 |
| Praat CPP         | [Parselmouth](https://github.com/YannickJadoul/Parselmouth) (Praat Python 绑定) | v5.18 | `enable_praat_cpp`           | 替换手动 FFT 倒谱，CPP 精度对齐学术标准               |
| Voicing detection | [pitch-benchmark](https://github.com/)                                          | v5.18 | `enable_voicing_detection`   | recall/FA 评估，提升 Pitch 检测可靠性                 |
| TorchCREPE 备选   | [CREPE](https://github.com/marl/crepe) (~5MB)                                   | v5.18 | `enable_torchcrepe_fallback` | PYIN 置信度低时降级启用                               |
| SVQTD 7属性分类器 | 论文[2210.17367v2](https://arxiv.org/abs/2210.17367)                            | v6.1  | `enable_svqtd`               | 歌唱属性: 颤音/滑音/假声/气声/共鸣/咬字/力度          |
| ECAPA-TDNN 音色   | [SpeechBrain](https://github.com/speechbrain/speechbrain)                       | v6.1  | `enable_ecapa_timbre`        | 音色分析: 明亮度/厚度 (填补 README 声明的音色功能)    |

### 3.3 ★ v6.0 新增 — 标准歌曲数据库 (轨道A)

> **架构关系**: 标准曲库是评分管线上层的增强模块。匹配成功时，注入参考音频到 DTW 对比路径；匹配失败时，无缝回退到核心绝对评分管线 — 所有 v5.x 和 v6.x 轨道B 的算法优化在回退路径中完全生效。

| 功能                   | 说明                                                                                                            | BDD 场景                |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------- |
| **标准曲库存储** | SQLite/JSON 存储歌曲元数据 (歌名/歌手/调性/BPM/难度/风格) + 预提取特征 (基频曲线/onset/频谱指纹)                | `database.feature`    |
| **曲库管理 API** | CRUD: 添加(单首+批量)/删除/搜索/筛选(风格/难度)/分页浏览                                                        | `database.feature`    |
| **自动音频匹配** | 上传音频 → 提取特征 → 多维度相似度搜索 (BPM/调性/频谱指纹) → 返回最佳匹配                                    | `auto-match.feature`  |
| **匹配回退机制** | 无匹配 (置信度<阈值) →**回退绝对评分** (完整的五维 Quick/Pro 管线)，标注 `fallback_reason: "no_match"` | `auto-match.feature`  |
| **选歌录音**     | 浏览曲库 → 选歌 → 录音 (实时音高对比) → DTW 对比评分                                                         | `song-select.feature` |
| **特征预计算**   | 歌曲入库时后台预提取所有特征，匹配时直接比对 (不重复计算)                                                       | `database.feature`    |
| **匹配缓存**     | 同一音频重复上传时复用匹配结果 (基于音频哈希)                                                                   | —                      |

> **回退不是降级**: 无匹配时的绝对评分仍然享受 v5.18 的 Feature Flag / 多尺度HNR / Praat CPP 以及 v6.0 轨道B 的校准数据集优化。匹配增强和算法优化是正交的两个维度。

### 3.4 ★ v6.0 全模式通用 — 实时音准对比显示 (P1)

> 类似全民K歌：音频播放时，用户音高曲线与标准音高曲线实时同步滚动，偏差用绿/橙/红着色。跨越 Quick、Pro、录音、对比四个模式。

| 功能                         | 适用模式           | BDD 场景                                               |
| ---------------------------- | ------------------ | ------------------------------------------------------ |
| **双曲线对比视图**     | 全部 (有参考时)    | 标准虚线 (#6366f1) + 用户实线 (绿/橙/红), 偏差色带填充 |
| **单曲线绝对音高**     | Quick/Pro (无参考) | 蓝色实线, 标注最高/最低音                              |
| **录音中实时音高反馈** | 选歌录音           | 标准虚线滚动 + 用户圆点 + 偏差数字 + 趋势箭头          |
| **DTW 叠加回放**       | 对比分析           | 对齐后双曲线 + 底部热力图 + 点击跳转                   |
| **偏差统计面板**       | 全部 (有参考)      | 精准率/略偏率/跑调率 百分比                            |
| **性能自适应**         | 全部               | ≥30fps 目标, 低性能设备自动降级 (关抗锯齿/简化着色)   |

**视觉规范**:

| 偏差                | 颜色                | 含义     |
| ------------------- | ------------------- | -------- |
| ≤ 25 音分          | #22c55e 绿色        | 精准     |
| 25-50 音分          | #f59e0b 橙色        | 略偏     |
| > 50 音分           | #ef4444 红色        | 跑调     |
| 无基频 (气声/辅音)  | #94a3b8 灰色虚线    | 检测中断 |
| 八度跳变 (可能误检) | #94a3b8 灰色 + ⚠️ | 不确定   |

**边界条件** (详见 `pitch-realtime.feature` 25 scenarios):

- 清辅音/气声 → 显示空白虚线, 不标记为跑调
- 八度跳变 → 标记 ⚠️, 不标记为跑调
- 首尾静音 → 自动裁剪
- 短音频 (<10s) → 缩放到填满视口
- 长音频 (>3min) → 视口窗口 + 缩略导航条
- 暂停/跳转/倍速/循环 → 曲线同步
- 标签页不可见 → 暂停渲染, 切回时瞬间更新
- 低性能设备 → 自动降级为性能模式

### 3.5 ★ v6.0 全模式通用 — 非阻塞分析 + 录音实时分析 (P1)

> 分析期间不锁界面、录音时后端同步分析、录完秒出结果。从「等进度条」到「分析透明化」的体验跃迁。

#### 3.5.1 非阻塞分析 (Quick/Pro/Compare)

| 功能                     | 说明                                                                | BDD 场景                         |
| ------------------------ | ------------------------------------------------------------------- | -------------------------------- |
| **细条进度条**     | 页面顶部 4px 进度条, 非模态, 不遮挡内容                             | `nonblocking-analysis.feature` |
| **维度逐步展示**   | 评分卡片区各维度图标依次亮起 (音准→节奏→气息→技术→艺术)         | 同上                             |
| **分析中可播放**   | 上传后立即可播放音频, 不等分析完成                                  | 同上                             |
| **分析中实时音准** | 收到基频数据后, 播放时即显示音准曲线 (有参考=双曲线, 无参考=单曲线) | 同上                             |
| **SSE 进度推送**   | `/api/analysis/progress?task_id=xxx` 推送阶段性事件               | 同上                             |
| **跨页面不中断**   | 切换到其他页面 → 迷你进度条 → 后台继续分析 → 完成后通知          | 同上                             |
| **无缝结果过渡**   | 分析完成时如正在播放 → 不打断, 评分数字动画出现                    | 同上                             |
| **优雅错误处理**   | 失败 → 红色进度条 + Toast (非模态) + 可重试                        | 同上                             |

#### 3.5.2 录音实时后台分析

| 功能                       | 说明                                                     | BDD 场景                      |
| -------------------------- | -------------------------------------------------------- | ----------------------------- |
| **Chunk 流式分析**   | 录音每 2s 一个 chunk 发后端, 后端立即开始特征提取        | `realtime-analysis.feature` |
| **录完秒出结果**     | 2min 录音 → 停止后 <10s 出完整评分 (vs 冷启动 20-40s)   | 同上                          |
| **短录音极速**       | <30s 录音 → 停止后 <3s 出结果                           | 同上                          |
| **实时质量反馈**     | 录音中检测音量/噪音/人声 → Toast 提醒 (不中断录音)      | 同上                          |
| **选歌时已知参考**   | 跳过匹配, 前端已有标准基频 → 录音中即实时对比           | 同上                          |
| **未选歌时自动匹配** | 录音完成后匹配 → 命中=DTW, 未命中=绝对评分              | 同上                          |
| **网络抖动容错**     | Chunk 失败 → 本地缓存 → 恢复补传 (sequence_index 排序) | 同上                          |

#### 3.5.3 SSE 事件协议

```
录音模式:  recording_started → chunk_processed* → pitch_stream* →
          partial_score* → quality_warning* → recording_stopped →
          matching? → final_score

上传分析:  voice_check → feature_pitch → feature_rhythm →
          feature_breath → feature_technique → scoring →
          matching? → complete
```

### 3.6 ★ v6.0 — 可配置评分系统 + 多维度分析 (P1)

> 评分权重可通过配置文件、风格预设、用户自定义三层控制。有参考音频时 DTW 是补充而五维是主体，两者各司其职。

#### 3.6.1 权重配置四层优先级 (无硬编码兜底)

| 优先级   | 来源                          | 适用场景                  |
| -------- | ----------------------------- | ------------------------- |
| 1 (最高) | 请求中指定的权重              | 对比分析时手动调参        |
| 2        | 歌曲关联配置 (曲库存储)       | 录入歌曲时保存的参数      |
| 3        | 用户本地预设                  | "我的预设" JSON           |
| 4        | 风格预设 (config/styles.yaml) | 流行/美声/民族/说唱默认值 |

> **设计决策**: 不设硬编码兜底。配置文件是唯一真相来源 (Single Source of Truth)。`config/styles.yaml` 缺失或格式错误 → 启动报 `ConfigError`，/health 返回 `config_status: "error"`，拒绝服务直到修复。任何降级行为都会掩盖配置错误。

#### 3.6.2 风格预设默认权重

| 风格 | Pitch | Rhythm | Breath | Technique | Artistry | 设计理由                              |
| ---- | ----- | ------ | ------ | --------- | -------- | ------------------------------------- |
| 流行 | 30%   | 20%    | 20%    | 20%       | 10%      | 均衡, 与 config/default.py 默认值一致 |
| 美声 | 30%   | 15%    | 25%    | 20%       | 10%      | 音准+气息优先, 节奏容忍度大(Rubato)   |
| 民族 | 28%   | 18%    | 18%    | 18%       | 18%      | 五维均衡, 各有特色                    |
| 说唱 | 10%   | 35%    | 10%    | 15%       | 30%      | 节奏+艺术核心, 音准次要               |

#### 3.6.3 有参考时的统一评分架构 ★v6.0 (DTW 降级)

```
标准音频 ─┐
          ├─ DTW 三级对齐 → 仅产出偏差数据
用户音频 ─┘    ├─ dtw_pitch_cents     (逐帧音分偏差)
               ├─ dtw_rhythm_offset   (逐帧节拍偏移)
               └─ alignment_confidence (全局置信度)
                          │
                          ▼
                 ScoreServiceV4 (唯一评分入口)
     ┌──────────┬──────────┬──────────┬──────────┬──────────┐
     │  Pitch   │ Rhythm   │ Breath   │ Tech     │ Art      │
     │ PYIN+DTW │ onset+DTW│ 四子维度  │ HNR/CPP  │ 四维复合  │
     │ DTW≤70%  │ DTW≤50%  │ DTW 不参与│ DTW 不参与│ DTW 不参与│
     └──────────┴──────────┴──────────┴──────────┴──────────┘
                          │
                          ▼
              total_score (五维加权) + advice
              + dtw_metadata (偏差摘要, 仅前端展示用)
```

> **关键变化**: DTW 不再产出 `dtw_score` 等独立评分。它是特征提供者, 为 pitch_scorer 和 rhythm_scorer 提供精确偏差数据。Breath/Technique/Artistry 完全不受 DTW 影响。学术依据: Bohm 2017 (DTW+特征融合 0.87 vs 纯DTW 0.52), Gupta 2021, Santos & Masiero 2026。

#### 3.6.4 系统推荐权重

| 分析维度   | 检测内容                    | 对权重的影响            |
| ---------- | --------------------------- | ----------------------- |
| 音域范围   | 最低音-最高音 (半音数)      | 跨度大 → Pitch +3~5%   |
| 节奏复杂度 | BPM变异性, 拍号, 切分音密度 | 复杂 → Rhythm +5~8%    |
| 长音占比   | ≥2s长音占乐句比例          | 多 → Breath +3~5%      |
| 技巧特征   | 颤音/滑音/假声/气声密度     | 密集 → Technique +3~5% |
| 动态范围   | RMS 标准差 (dB)             | 大 → Artistry +3~5%    |

推荐在 5 秒内完成，逐维度给出调整理由。用户可一键应用或微调后保存为自定义预设。

#### 4.1.7 性能降级策略

> 当硬件资源不足时，系统应优雅降级而非崩溃。

| 场景                        | 降级行为                                         | 触发条件                                         |
| --------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| **内存不足**          | 跳过 Demucs 分离，回退 Quick 评分 + warning      | 可用 RAM < 2GB                                   |
| **GPU 不可用**        | 自动切换 CPU 模式 (Demucs ~140s)                 | `torch.cuda.is_available() == False`           |
| **低性能设备 (前端)** | 动画禁用，Canvas 30fps 低精度模式，关抗锯齿      | `navigator.hardwareConcurrency < 4` 或用户设置 |
| **超大文件**          | 拒绝 > 50MB，返回 413                            | Content-Length > 50MB                            |
| **超长音频**          | > 10min 仅 Quick 模式，Pro 模式警告              | duration > 600s                                  |
| **Demucs 失败**       | 回退原始音频评分 + warning                       | 分离进程超时/崩溃                                |
| **DTW 对齐失败**      | 回退绝对评分 (五维管线完整) +`fallback_reason` | DTW 异常/超时                                    |

## 9. ★ v7.0 — Electron 桌面应用 + Vue 3 前端重构 (规划中)

### 9.1 目标

将系统从 **浏览器 Web 应用** 升级为 **独立桌面应用**, 同时将前端从 **Vanilla JS SPA** 重构为 **Vue 3 组件化架构**。

> **v5.20 准备**: AppContext (依赖注入) + EventBus (事件总线) 已就绪。
> 所有组件通过 `this.context.*` 访问服务, 生命周期已对齐 Vue (`mount` → `onMounted`, `beforeUnmount` → `onBeforeUnmount`)。
> 迁移时 AppContext → `app.provide`, EventBus → `mitt`, HashRouter → Vue Router。

### 9.2 技术选型

| 层级 | 当前 (v5.x) | 目标 (v7.0) | 理由 |
|------|------------|------------|------|
| **桌面框架** | — (浏览器访问) | Electron 28+ | 跨平台 (Win/Mac/Linux), 原生窗口, 系统托盘 |
| **前端框架** | Vanilla JS ES6 模块 | Vue 3 (Composition API) | 组件化, 响应式, 生态丰富, 可维护性 |
| **构建工具** | — (直接加载) | Vite 5+ | 快速 HMR, 开箱即用 TypeScript, 打包优化 |
| **依赖注入** | AppContext (自研) 🆕 | Vue provide/inject | 已对齐, 迁移成本极低 |
| **事件通信** | EventBus (自研) 🆕 | mitt() | API 完全一致, 可直接替换 |
| **状态管理** | 自研 Store (Proxy) | Pinia | Vue 3 官方推荐, DevTools 支持 |
| **路由** | HashRouter (useContext) | Vue Router 4 | 官方路由, 导航守卫, 懒加载 |
| **动画** | GSAP 3 (保留) | GSAP 3 + VueUse | GSAP 保持不变, VueUse 补充 |
| **图表** | Chart.js | Chart.js + vue-chartjs | 保留 Chart.js, 添加 Vue 封装 |
| **后端** | Python Flask | Python Flask (不变) | 后端评分管线不变, 仅部署方式改变 |
| **进程模型** | 单进程 Flask | Electron 主进程 + Flask 子进程 | 主进程管理窗口, Flask 在后台运行 |
| **打包** | 手动 `python web_app.py` | electron-builder + PyInstaller | 一键安装包 (.exe/.dmg/.AppImage) |
