# 前端真实页面视觉审计

> ⚠️ **历史证据 (2026-06-06)**: 本审计基于 2026-06-06 的 v5.x Vanilla JS 前端 (`web/static/`)。当前 v7.9 前端已完全重建为 Vue 3 + Element Plus (`frontend/src/`)，不再使用 emoji 图标、内联样式、旧 CSS 布局。本文档中所有具体视觉问题（sidebar、top-nav、inline style 计数）不再适用于当前前端。设计原则部分仍具参考价值。
>
> 审计日期: 2026-06-06 | 审计范围: 旧版 `web/static/` (Vanilla JS SPA) | 文档版本: v7.9 (此文档反映的是 2026-06-06 时的旧前端状态)

## 1. 总体结论

当前前端已经具备 SPA 基础、组件拆分和 GSAP 文件结构，但真实页面仍更像“功能样例集合”，还不是一个成熟的声乐练习与评估产品。页面主要问题不是单个颜色或卡片样式，而是信息架构、视觉语言、移动端优先级和后端能力预留同时失焦。

必须先重做页面职责和视觉系统，再继续堆功能。否则标准曲库、自动匹配、评分参数、非阻塞分析等后端能力接入后，会再次放大当前的杂乱结构。

## 3. 页面级问题

### 3.1 Home

Home 应该是工作台入口，而不是产品介绍页。当前首页把上传、录音、模式选择、使用说明、五维评分比例、技巧提示混在一起，导致用户无法在第一眼判断“现在应该做什么”。

需要删除或后移的内容:

| 内容 | 处理 |
|------|------|
| 未分析前的五维评分比例 | 移到结果页或评分参数说明页 |
| 静态改进建议/技巧样例 | 移到报告页或练习建议模块 |
| 大量 emoji 能力标签 | 改为图标系统、文字标签或纯排版层级 |
| 移动端提前显示 sidebar | 移除 `order: -1`，保证主操作优先 |

Home 应保留并强化的入口:

| 入口 | 目标路由 |
|------|----------|
| 上传录音分析 | `#/` -> 分析任务 -> `#/report/:analysisId` |
| 快速录音练习 | `#/sing` |
| 手动标准音频对比 | `#/compare` |
| 标准曲库练习 | `#/library` 或空状态预留 |

### 3.2 Compare

Compare 目前已经有“标准音频 + 我的演唱”的基础路径，但真实页面仍像占位卡片，缺少专业对比工具应有的结构。

必须预留的状态:

| 状态 | 原因 |
|------|------|
| 标准音频上传成功/失败/处理中 | 当前后端已有 `/api/compare` 和 `/api/extract-pitch` |
| 从曲库选择标准歌曲 | 对齐 `database.feature` 与 `song-select.feature` |
| 自动匹配成功、候选列表、fallback | 对齐 `auto-match.feature` |
| 评分参数来源和权重摘要 | 对齐 `scoring-config.feature` |
| 对比完成后的偏差段落 | 避免只展示雷达图或大卡片 |

### 3.3 Settings

Settings 当前只是基础偏好页，不足以支撑后端路线。它应拆成“偏好设置、评分参数、模型与算法、数据管理”四个模块。

建议拆分:

| 路由 | 页面职责 |
|------|----------|
| `#/settings` | 主题、默认模式、自动跳转、缓存 |
| `#/settings/scoring` | 五维权重、风格预设、推荐权重、自定义预设导入导出 |
| `#/settings/models` | Feature Flag、GPU 状态、模型可用性、实验算法说明 |
| `#/settings/data` | 历史记录、缓存、备份与恢复 |

## 4. 视觉系统要求

当前页面不应继续以“换色 + 圆角卡片 + emoji”方式优化。下一轮应先确定一个明确视觉方向，例如“录音棚工作台”：克制、专业、有声波和谱线质感，强调声乐分析的可信度。

| 维度 | 验收要求 |
|------|----------|
| Typography | 建立标题、数字、说明、标签四级层级，避免默认浏览器观感 |
| Color | 使用有限调色板，主色服务录音/分析状态，不做随机彩色 chip |
| Layout | 首页第一屏只服务开始任务，说明内容降级为次级区域 |
| Surface | 卡片、面板、上传区、结果区使用同一套边框/阴影/背景规则 |
| Icon | 不再用 emoji 作为结构图标；使用 SVG、CSS 图形或纯文字标签 |
| Motion | GSAP 只用于页面进入、任务进度、分数揭示、路由过渡等关键时刻 |
| Mobile | 375px 首屏必须优先显示上传/录音/对比入口，不显示技巧样例优先于任务 |

## 5. GSAP 与视频样例验收

GSAP 已有文件结构，但缺少可审美验收的样例。下一阶段应把动效做成可复现的 motion spec 和录屏资产。

| 场景 | 动效目标 | 验收资产 |
|------|----------|----------|
| Home 首次进入 | 建立产品气质，突出上传/录音入口 | 10-15 秒桌面录屏 |
| 上传后分析中 | 表达非阻塞进度和阶段性特征 | 15-20 秒录屏 |
| Report 分数揭示 | 分数、维度、问题段落按重要性出现 | 20 秒录屏 |
| Compare 对比完成 | 标准/用户轨迹和偏差段落形成叙事 | 20 秒录屏 |
| Reduced motion | 禁用强位移和长过渡 | 浏览器检查记录 |

## 6. 性能审计补充

基于浏览器真实页面检查的性能发现：

| 页面 | 问题 | 影响 | 建议 |
|------|------|------|------|
| Home | 27 个 inline style 节点 | 样式计算延迟，每次重绘触发 CSSOM 重建 | 全部迁移到 CSS 变量 |
| Home | 侧边栏渲染时机 | 移动端在首屏前渲染 (order:-1)，延迟 LCP | 移动端侧边栏延迟加载 |
| Compare | 47 个 inline style | 对比页样式计算开销大 | 迁移到组件 CSS |
| Settings | 38 个 inline style | 同上 | 同上 |
| 所有页面 | GSAP 绑定的 DOM 元素无 `will-change` | 动画触发不必要的 repaint | 动画前后动态设置/移除 `will-change` |
| SingPage | Canvas 200px 高度 | 低分辨率设备渲染吃力 | 按设备像素比动态缩放 |

## 7. BDD 跳转验收补充

现有 BDD 已覆盖 navigation、animations、database、song-select、scoring-config 等方向，但前端页面还没有完全按这些场景收束。建议新增或强化以下 Gherkin 语义:

| 行为 | 期望 |
|------|------|
| 用户进入首页 | 首屏看到上传、录音、对比、曲库入口，而不是评分样例 |
| 移动端进入首页 | 主操作区在说明区之前 |
| 用户上传音频并分析成功 | 自动进入 `#/report/:analysisId`，刷新可恢复 |
| 用户打开对比页 | 可选择标准音频、用户音频、评分参数或曲库标准歌 |
| 用户打开设置页 | 可进入评分参数和模型状态子页面 |
| 用户访问未实现 v6.0 页面 | 显示“后端待接入”的空状态，而不是 404 或假功能 |
