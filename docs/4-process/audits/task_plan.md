# 声乐项目状态审计与前端优化计划

## Goal

梳理项目已经完成的能力、当前存在的问题，并形成后续优化计划，重点覆盖前端审美、结构、GSAP 动效、BDD 跳转逻辑、文档模块化，以及前端与后端 v5.18/v6.0 计划的对齐。

## Phases

| Phase                 | Status   | Output                                                                               |
| --------------------- | -------- | ------------------------------------------------------------------------------------ |
| 1. 现状扫描           | complete | Git 状态、文档、前端页面、BDD/E2E 路由、GSAP 使用情况                                |
| 2. 问题归类           | complete | 按产品、前端、测试、文档、算法/性能分类                                              |
| 3. 路线图设计         | complete | P0/P1/P2 优化计划与验收标准                                                          |
| 4. 文档结构收口       | complete | 审计文档迁入 `docs/4-process/audits/`，前端文档迁入 `docs/2-technical/frontend/` |
| 5. 前后端对齐         | complete | 标准曲库、自动匹配、参数设置、非阻塞分析的前端预留页面计划                           |
| 6. 浏览器真实页面审计 | complete | Home/Compare/Settings 桌面与移动端抽样，输出 `VISUAL_AUDIT.md`                     |

## Constraints

- 审计和计划文档统一放在 `docs/` 下，不在项目根目录散放。
- 不改业务代码，先做状态梳理、文档结构和路线图。
- 保留用户或当前工作区已有改动，不回滚、不清理未提交内容。
- 前端计划必须与 PRD、GOALS、BDD 中的后端计划对齐。
