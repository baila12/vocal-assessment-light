# 项目审计与后续优化计划

> 日期: 2026-06-06
> 目标: 明确已完成能力、当前问题和下一阶段优化路线，重点收束前端体验、BDD 跳转逻辑、GSAP 动效、文档体系，以及前端与后端 v5.18/v6.0 计划的对齐。

---

## 1. 当前结论

项目后端和算法能力已经进入可用阶段，Quick、Professional、Compare 三种评估模式有比较完整的实现和真实音频验证记录。当前主要瓶颈已经从“能不能评估”转向“用户是否愿意使用、是否信任结果、前端是否足够专业”。

前端目前处在重构中间态：新的 SPA 架构已经搭起来，但旧多页面结构、旧 E2E 断言、emoji 化视觉表达、样例式首页内容和零散动效还没有收束。下一阶段不宜继续堆页面元素，应先完成前端信息架构、路由契约和设计系统的重新定义。

同时，后端还没有完善到 v6.0 目标状态。前端必须预留标准歌曲库、添加标准音频、评分参数设置、自动匹配、选歌录音、非阻塞分析等页面和状态，否则后续后端能力接入时会再次推翻页面结构。

本轮已使用浏览器检查静态 SPA 真实页面。静态预览 `http://localhost:8000/` 正常可访问，Flask `http://localhost:5000/` 在 3 秒检查中超时，需要作为后端启动/验证风险单独排查。真实页面证据已同步到 [../../2-technical/frontend/VISUAL_AUDIT.md](../../2-technical/frontend/VISUAL_AUDIT.md)。

## 3. 当前问题

### 3.1 P0: 前端产品体验不成立

| 问题                          | 证据                                                                                     | 影响                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 首页信息架构混乱              | 首页同时呈现上传、录音、模式选择、使用说明、五维权重、技巧提示                           | 用户第一眼不知道核心任务是什么                      |
| 页面像样例展示而非工具        | 五维评分比例、建议块、技巧提示在未分析前就出现                                           | 结果区域和工作流区域边界不清                        |
| emoji 大量参与 UI             | `HomePage.js`、`ReportPage.js`、`ComparePage.js`、`SingPage.js` 中直接使用 emoji | 视觉廉价、风格不稳定、难以建立专业感                |
| 旧页面与新 SPA 并存           | `analysis.html`、`compare.html`、`settings.html` 仍存在，新路由又重定向旧入口      | 维护成本高，测试和用户路径冲突                      |
| 组件结构夹杂大量 inline style | 页面 JS 中直接写样式和展示结构                                                           | 难以形成统一设计系统，后续迭代会继续变乱            |
| 移动端首屏优先级错误          | 浏览器抽样显示 Home 的 `.sidebar` 在 375px 下 `order: -1`                            | 小屏用户先看到说明/评分/技巧，而不是上传/录音主操作 |
| 移动端导航不完整              | 抽样显示移动底部导航只有首页、演唱、对比、历史，缺少设置                                 | 用户难以进入偏好、参数、模型状态等后续关键页面      |

### 3.1.1 浏览器真实页面审计摘要

| 页面          | 抽样发现                                                                                          | 优先级 |
| ------------- | ------------------------------------------------------------------------------------------------- | ------ |
| Home 桌面     | 首屏同时出现能力标签、上传、录音、模式、说明、五维评分和技巧提示；emoji 约 10，inline style 约 27 | P0     |
| Home 移动     | `.sidebar` 被提前，说明内容和五维评分优先于核心操作                                             | P0     |
| Compare 桌面  | 有标准音频/我的演唱入口，但仍像占位卡片；emoji 约 6，inline style 约 47                           | P1     |
| Settings 桌面 | 只有主题、模式、自动跳转、缓存；没有评分参数、模型状态、Feature Flag、GPU 状态                    | P0     |

### 3.2 P0: 跳转逻辑和测试体系冲突

| 问题                   | 证据                                                                             | 影响                     |
| ---------------------- | -------------------------------------------------------------------------------- | ------------------------ |
| 新旧路由契约冲突       | 新单测要求旧 HTML 301 到 `/`，旧 E2E 仍期待 `analysis.html`/`compare.html` | 测试无法稳定成为质量闸门 |
| BDD 未成为跳转单一真相 | `navigation.feature` 已存在，但旧 E2E 仍分散定义路径期望                       | 需求变更时容易漏改       |
| 报告页刷新恢复不完整   | BDD 写了 `#/report/42` 刷新恢复，但当前 ReportPage 主要依赖 store              | 刷新后用户可能丢失结果   |
| 无效路由 Toast 未闭环  | BDD 期待“页面不存在”提示，Router 当前主要 console.warn + replace               | 行为与验收定义不一致     |

### 3.3 P1: 前端没有与后端计划对齐

| 问题                    | 证据                                                         | 影响                          |
| ----------------------- | ------------------------------------------------------------ | ----------------------------- |
| 标准曲库页面缺失        | PRD 和 BDD 已有 database/song-select，但前端无 `#/library` | v6.0 接入时会重拆信息架构     |
| 评分参数页缺失          | `scoring-config.feature` 已定义权重滑块、预设、推荐权重    | 设置页无法承载后续评分配置    |
| 非阻塞分析缺少任务模型  | BDD 已定义 SSE 阶段事件和跨页面不中断                        | 上传分析仍容易做成阻塞式 UI   |
| Feature Flag 无前端入口 | v5.18 计划实验算法开关                                       | 用户无法知道当前算法/模型状态 |

### 3.4 P1: GSAP 使用有量但没有统一语言

| 问题               | 证据                                                                | 影响                   |
| ------------------ | ------------------------------------------------------------------- | ---------------------- |
| 动效分散           | 页面组件、effects、components 中各自调用 GSAP                       | 动效节奏不统一         |
| 缺少 motion spec   | 没有统一定义 entrance、transition、score reveal、reduce motion 规则 | 很难审美验收           |
| 减动偏好未全局闭环 | BDD 有 prefers-reduced-motion 场景，但实现分散                      | 可访问性存在缺口       |
| 缺少视频样例       | 没有用视频/录屏作为动效验收资产                                     | “好看”无法复现和比较 |

## 5. 验收标准

| 类别       | 标准                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 文档       | 审计和前端文档都位于 `docs/` 对应目录                                                 |
| 视觉       | 页面不再依赖 emoji 表达结构；首页第一屏清晰指向上传/录音/对比/曲库练习                  |
| 信息架构   | 每页职责明确，首页不展示未分析前的评分样例和建议样例                                    |
| 路由       | 所有主流程使用 hash route，旧 HTML 页面只有迁移入口职责                                 |
| 后端对齐   | 前端预留标准曲库、参数设置、Feature Flag、非阻塞分析页面                                |
| BDD        | navigation、offline、animations、database、song-select、scoring-config 可对应到页面职责 |
| 动效       | 页面进入、报告生成、分析进度、Toast 都有统一 GSAP 规则                                  |
| 浏览器检查 | 实际 UI 改造阶段必须用浏览器检查桌面和移动端                                            |
